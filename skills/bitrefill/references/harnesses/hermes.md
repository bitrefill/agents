# Host: Hermes Agent

> Internal mechanics — never voiced. Speak / think / title tools in plain shopping language: "sign in with your wallet", "approve the payment", "your code is ready"; never x402 / SIWX / JWT / path / endpoint.

The Bitrefill plugin gives Hermes this skill and the Bitrefill connector; its tools arrive as `mcp__bitrefill__<tool>` (`-` → `_`). The connector's sign-in belongs to the Hermes profile owner and is shared by every chat of that profile. Route silently:

1. **Connected** (`mcp__bitrefill__get_balances` in your tool list) → [../touchpoints/mcp.md](../touchpoints/mcp.md). No `mcp__bitrefill__*` tool listed = not connected (the connector is signed out); go to 2 without `tool_search`.
2. **Not connected**, `terminal` and `command -v npx` → guest checkout ([../touchpoints/cli.md](../touchpoints/cli.md) § Guest checkout), every call as `npx -y @bitrefill/cli@0.3.0 <command> … --json`, never `npm install -g`, `npm link` or another install outside the working folder, with `--payment_method <method>` last before `--json`; `cart_items` take `package_value` as a string (`[{"product_id":"steam-usa","package_value":"20"}]`). Buy only while `whoami --json` returns `"identity":"unregistered"`. A bare-string result, or `error` / `message` instead of the expected fields, failed, even on exit 0 (the CLI drops `isError`). Offer "Connect your Bitrefill account" first in the confirm; if picked, the owner signs in on the Hermes machine ([../touchpoints/mcp.md](../touchpoints/mcp.md) § Hermes Agent), never in chat: never ask for a password, code, key or sign-in address here. Guest `purchase_limit_reached` → offer the connect again. Hermes never prompts before a `terminal` command, so the confirm is the only gate: call guest `buy-products` only after the user's own reply accepts the quoted product, amount, total, method and email.
3. **Neither**, or the method is rejected → send the `https://www.bitrefill.com` product link.

Product, confirm and payment → [grok-bot.md](grok-bot.md) § Product first, one confirm and § Pay; no address came back → offer the `payment_link` checkout, never a second `buy-products` without a new confirm. Invoice total above the confirmed one → say so and get a new yes before the user pays. `x402_payment_url`: only through a wallet that asks the user to approve each payment ([../wallets/base-mcp.md](../wallets/base-mcp.md)); else post the address or `payment_link`.

## Hermes

- After the confirm, call `buy-products` once: Hermes asks the user to approve every order, `/yolo` included, and each answer covers only that order. Never answer that prompt; never suggest **Always**, `/yolo`, `approvals.mode: off` or a higher spend limit; never run `hermes` commands or `manage_connections`, or change Hermes settings. Denied, cancelled, timed out or spend limit reached → stop: nothing was bought; never retry, rephrase or switch route. Uncertain outcome (`outcome_uncertain` in the tool error) → check `list-invoices` first and tell the user; never buy again without a new confirm. Autonomous buying still gets that prompt; only the user changes it, in their own settings.
- Buy only in a local session (CLI, TUI, Desktop) or where **Source** is a chat app followed by `("DM with …")`, never when Source is Api_Server, Email, Sms, Ntfy or Webhook. Groups, channels and threads are read by others: reply there only "DM me to finish this". Use the connector only in the owner's chat; anyone else shops as a guest. Cron jobs, webhooks and other unattended runs never buy. One-shot runs (`hermes -z`, `-Q`, `-q`) never use the connector to buy; a guest order there needs the confirm in that run's message, since it only opens an invoice the user pays.
- `terminal` is guest checkout only: never `login`, `verify`, `--payment_method balance` / `cashback`, `--saved_fiat_card_id`, AgentCash, `awal`, `scripts/` or any payer that settles without its own approval; never `execute_code` for Bitrefill or `hermes`; never read `~/.config/bitrefill-cli/` or Hermes token files. Balance, cashback and saved cards only through the connector.
- Codes, `invoice_access_token` and `payment_link` stay in this chat: never `memory`, files, `cronjob_manage` or `text_to_speech`; never echo the token to the user (Hermes already keeps tool results in its session history).

**User hears:** "Searching for [product]…" → "[Product] [amount]: [total] [currency] (≈ $X) by [method]. Confirm?" → "Approve the order in the prompt." → "Send [amount] [coin] on [network] to [address]" or "Pay here: [link]" → "Your code is ready." / "Done — topped up."
